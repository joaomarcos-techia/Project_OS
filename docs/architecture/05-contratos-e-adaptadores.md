## Regras comuns

- **Identidade interna:** mapear `(issuer, subject)` para UUID Qoro estável; não usar e-mail como chave de migração. O schema atual liga profiles.id a auth.users: é necessário expand-and-contract aprovado, não só mapper em TypeScript.
- **Dinheiro:** propor amountMinor em BRL nos contratos novos, preservando arredondamento observado nas fronteiras atuais. Migrar unidades é mudança de contrato com fixtures de centavos; não reinterpretar numeric já persistido.
- **Transação:** não há transação ACID entre DB e provider. Reservar operação local, chamar rede fora do lock longo, reconciliar efeito incerto e finalizar localmente com guarda. Nenhum contrato promete exactly-once de rede.
- **Namespace financeiro:** `{provider, accountRef, externalId}` sempre. Idempotência `{operationId, operationKind, accountRef}`; event dedup `{provider, accountRef, eventId}`. Conta SaaS não é conta recebedora de paciente.
- **Capacidades:** listar hosted recurrent checkout, charge lookup por referência, refund readback, métodos/ciclos e alterações pendentes. Operação unsupported não vira emulação financeira automática.
- **Versionamento:** v1 de eventos/DTOs internos com leitores compatíveis durante janela. Alteração semântica pede nova versão e fixture antiga, não cast. Não armazenar payload clínico ou financeiro bruto apenas para facilitar replay.
- **Falhas:** classificar erro definitivo, transitório e resultado desconhecido. Unknown exige readback/operador, nunca criação imediata no gateway secundário.
- **Teste de contrato:** mesma suíte de capacidades em Asaas e adapter alternativo; fake protege domínio, Sandbox prova API, E2E prova persistência/UI. Simulador não homologa mandato, token de cartão ou liquidação real.

## Evolução financeira sugerida

Preservar `PaymentProvider` e facade atuais durante extração; separar DTO canônico de DTO de transporte; mover construtor Asaas para adapter; adicionar registry por binding persistido; adaptar um caso de uso por PR; só depois schema para coexistência. Não permitir que uma env global `PAYMENT_PROVIDER` redirecione contratos antigos ou refunds.
