## Regras de segurança e evidência

1. Escritas externas apenas em DEV, Preview isolado e Asaas Sandbox explicitamente confirmado. Não alterar produção nem dados reais sem autorização específica atual. Nunca imprimir, copiar para logs ou versionar `.env.local`, chaves, passwords, bypass tokens, cookies, cabeçalhos Authorization, URLs assinadas ou payload clínico. Use somente nomes de variáveis e estados presente/ausente.
2. Antes de testes que criem cobrança, webhook, Auth user, clínica ou fixture, confirme host/projeto/conta Sandbox por identificadores públicos, limite de escopo, estado inicial e plano de cleanup. Leia o código do runner. Depois faça readback terminal no provider e no DEV; se cleanup falhar, preserve a fixture e documente. Não faça mutação em produção para deixar o teste verde.
3. Resultados possíveis: PASS = comportamento real executado e assertion comprovada; FAIL = comportamento incorreto observado; BLOCKED = precondition externa legítima; SKIP = omissão deliberada da suíte; NOT RUN = ainda não executado. Teste unitário, código existente, invocação de runner, deploy e HTTP 200 isolado não são PASS E2E.
4. Antes de commit: `git status`, `git diff --stat`, `git diff`, `git diff --check`. Commit apenas arquivos próprios. Não use `pnpm <script>` neste worktree com `node_modules` compartilhado; use binários diretos em `node_modules/.bin` ou `node node_modules/...`. Verifique comandos reais em `package.json` antes de executar.
5. Não reduza threshold, apague/desative teste, relaxe autorização, crie mock para esconder integração real ou ajuste expectativa ao defeito observado. Se um gate falhar, investigue e corrija a causa. Regenere `docs/security/acoes.md` com `node_modules/.bin/tsx.cmd scripts/security/inventory.ts --write` se mudar server actions; depois execute `--check`.
